# v2 Gameplay Completion Status

本文档最初记录旧版 UI 已表达、但 v2 架构尚未完整接入的功能。当前 `codex/avalon-work` 已补齐完整一局闭环和第一版朋友局线上体验。

## 当前已实现

- 队长选择出征队伍：`select_team` 命令、队伍选择弹层、服务端队长/人数/成员校验。
- 全员组队投票：`team_vote` 命令、通过/否决结算、公开票数摘要且不泄漏个人票。
- 出征队员提交任务票：`mission_vote` 命令、队员权限校验、失败票数量和比分公开。
- 任务结果复盘后进入下一轮：房主执行 `continue_after_result`。
- 刺客刺杀梅林：`assassinate` 命令、终局胜负和身份公开。
- 公开历史：`public_timeline` 投影开局、选队、组队结果、任务结果、轮次推进和刺杀结果。
- 终局身份公开：`GAME_OVER` 才返回 `reveal_roles`。
- 文字公屏：`send_chat` 命令，按阶段自动控场。
- 语音客户端：LiveKit 配置存在时可连接，未配置时降级。
- 在线状态：WebSocket 连接/断开广播 `online_state`。
- 房主治理：大厅踢人、转交房主、玩家退出。
- 私人标记：本地 `localStorage` 标记。

## 历史缺失清单

以下 P0/P1 条目是本文档最初记录的历史缺口，用于追溯 v2 gameplay completion 的补齐范围。它们不再表示当前版本无法完成一整局。

## P0：历史上阻断完成一整局的缺失功能

这些功能曾经不补齐就无法在 v2 页面里完成一局完整游戏；当前已完成接入。

### 1. 队长选择出征队伍

- UI 入口：`TEAM_PROPOSAL` 阶段的“选择出征队伍”按钮。
- 历史状态：按钮曾灰置；服务端快照能告诉当前玩家是否为队长，领域模型已有 `AvalonGame.select_team()`。
- 缺失项：
  - `CommandGateway` 支持 `select_team` 命令。
  - HTTP / WebSocket 命令请求校验 `team` 参数。
  - 提交后广播进入 `TEAM_VOTE` 的私有快照。
  - 前端队伍选择弹层启用，并按 `required_team_size` 限制人数。

### 2. 全员组队投票

- UI 入口：`TEAM_VOTE` 阶段的“赞成 / 反对”按钮。
- 历史状态：按钮曾灰置；领域模型已有 `AvalonGame.submit_team_vote()`。
- 缺失项：
  - `CommandGateway` 支持 `team_vote` 命令。
  - 防重复提交和阶段校验的应用层测试。
  - 投票完成后广播进入 `MISSION_VOTE` 或回到 `TEAM_PROPOSAL`。
  - 公开历史记录本轮组队是否通过，但不泄漏个人投票，除非后续规则明确要公开。

### 3. 出征队员提交任务票

- UI 入口：`MISSION_VOTE` 阶段的“任务成功 / 任务失败”按钮。
- 历史状态：按钮曾灰置；领域模型已有 `AvalonGame.submit_mission_vote()`。
- 缺失项：
  - `CommandGateway` 支持 `mission_vote` 命令。
  - 只有当前队伍成员可提交任务票。
  - 好人阵营是否允许提交失败票需要规则层明确。当时 `friend_flexible` 快照只表达 `can_submit_fail`，但应用层尚未执行。
  - 投票完成后广播比分变化、任务失败票数量和下一阶段。

### 4. 任务结果复盘后进入下一轮

- UI 入口：`MISSION_RESULT_DISCUSSION` 阶段的“进入下一轮”按钮。
- 历史状态：按钮曾灰置；领域模型已有 `AvalonGame.continue_after_mission_result()`。
- 缺失项：
  - `CommandGateway` 支持 `continue_after_result` 命令。
  - 明确谁可以推进：建议第一版由房主推进，后续可改为讨论计时或发言轮结束自动推进。
  - 推进后重置当前队伍、票、队长，并广播下一轮 `TEAM_PROPOSAL`。

### 5. 刺客刺杀梅林

- UI 入口：`ASSASSINATION` 阶段的“选择刺杀目标”按钮。
- 历史状态：按钮曾灰置；领域模型已有 `AvalonGame.submit_assassination()`。
- 缺失项：
  - `CommandGateway` 支持 `assassinate` 命令。
  - 前端刺杀目标弹层启用。
  - 只有刺客可提交，且只能提交一次。
  - 提交后进入 `GAME_OVER` 并广播胜利方。

### 6. 公开历史和任务结果事件

- UI 入口：历史弹层、法官公告、任务结果复盘文案。
- 历史状态：页面已保留历史入口，但 `public_timeline` 仍为空。
- 缺失项：
  - 应用层事件投影公开历史：开局、队长、队伍名单、组队是否通过、任务成功/失败、失败票数量、比分、刺杀结果。
  - 历史不得泄漏秘密任务票提交者、未公开身份表或夜间可见信息。
  - 快照需要稳定返回 `public_timeline`。

### 7. 终局身份公开

- UI 入口：终局阶段、信息弹层、历史弹层。
- 历史状态：`GAME_OVER` 只显示胜利方，未公开全员身份。
- 缺失项：
  - 快照新增终局 `reveal_roles`，仅在 `GAME_OVER` 返回。
  - 前端终局展示所有玩家身份与阵营。
  - 测试确保非终局不泄漏全员身份。

## P1：历史上阻断成熟线上体验的缺失功能

### 8. 文字公屏

- UI 已恢复但发送框曾灰置。
- 需要服务端接收、广播、持久化或短期保留聊天消息。
- 需要按阶段和发言控制决定谁可发言。

### 9. 语音客户端接入

- 顶部语音和扬声器按钮曾灰置。
- 后端已有 `/voice-token`，但当时前端未接 LiveKit 客户端。
- 需要按 `voice_state.can_publish_audio` 控制麦克风发布权限。

### 10. 发言控制和在线状态

- 旧产品目标包含发言控制、在线状态、断线重连提示。
- 当时 v2 只有 WebSocket 鉴权连接，没有公开在线列表、发言人、发言结束或强制切换命令。
- 需要快照新增 `online_state`、`speaker_state` 或等价字段。

### 11. 房主治理操作

- 旧 UI 有踢人、重置、复制邀请等治理入口。
- 当时 v2 只保留重置和邀请链接，缺少踢人、转移房主、游戏开始前退出/重连复用身份。

### 12. 私人标记

- 旧 UI 有私人标记入口，当时按钮灰置。
- 第一版可以先做纯本地 `localStorage`，后续再考虑服务端跨设备同步。

## 完整一局覆盖检查

完成一整局游戏的最小路径是：

1. 玩家加入房间。
2. 玩家准备，房主开局。
3. 每个玩家查看自己的身份和可见信息。
4. 队长选择队伍。
5. 全员对队伍投票。
6. 若队伍被否决，切换队长并重新组队。
7. 若队伍通过，出征队员提交任务票。
8. 服务端结算任务结果并更新比分。
9. 未达到终局时进入下一轮。
10. 正义三次任务成功后进入刺杀。
11. 刺客提交刺杀目标。
12. 服务端结算胜负并终局公开身份。

当前 v2 已覆盖第 1-12 步的完整一局链路。P0 第 1-7 项已经补齐规则闭环；P1 第 8-12 项已经形成第一版朋友局线上体验，后续仍可继续增强生产持久化、多端恢复和更完整的自动化浏览器验收。
