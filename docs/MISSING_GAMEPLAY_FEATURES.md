# v2 缺失功能清单

本文档记录旧版 UI 已表达、但当前 v2 架构尚未完整接入的功能。它是下一轮功能完善的来源。

## 当前已实现

- 房间加入：`POST /api/rooms/{room_id}/join` 创建玩家、席位、房主和 session token。
- 实时连接：`/ws/{room_id}` 使用首条 `hello + session_token` 鉴权，并按玩家广播私有快照。
- 大厅准备：`ready` 命令可切换玩家准备状态。
- 房主开局：`start_game` 命令可创建 `friend_flexible` 规则局，服务端分配身份并返回私有身份信息。
- 房主重置：`reset` 命令可回到大厅并保留玩家席位。
- 规则领域模型：`AvalonGame` 已有组队、组队投票、任务投票、任务结果后继续下一轮、刺杀和胜负判断方法。
- 快照隐私：服务端只给当前玩家自己的身份信息，不广播全量角色表、组队票或任务票。
- 旧 UI 壳恢复：圆桌座位、法官公告、当前操作、文字公屏、信息/历史/身份牌弹层已回到旧版结构和视觉。

## P0：阻断完成一整局的缺失功能

这些功能不补齐，就无法在 v2 页面里完成一局完整游戏。

### 1. 队长选择出征队伍

- UI 入口：`TEAM_PROPOSAL` 阶段的“选择出征队伍”按钮。
- 当前状态：按钮已灰置；服务端快照能告诉当前玩家是否为队长，领域模型已有 `AvalonGame.select_team()`。
- 缺失项：
  - `CommandGateway` 支持 `select_team` 命令。
  - HTTP / WebSocket 命令请求校验 `team` 参数。
  - 提交后广播进入 `TEAM_VOTE` 的私有快照。
  - 前端队伍选择弹层启用，并按 `required_team_size` 限制人数。

### 2. 全员组队投票

- UI 入口：`TEAM_VOTE` 阶段的“赞成 / 反对”按钮。
- 当前状态：按钮已灰置；领域模型已有 `AvalonGame.submit_team_vote()`。
- 缺失项：
  - `CommandGateway` 支持 `team_vote` 命令。
  - 防重复提交和阶段校验的应用层测试。
  - 投票完成后广播进入 `MISSION_VOTE` 或回到 `TEAM_PROPOSAL`。
  - 公开历史记录本轮组队是否通过，但不泄漏个人投票，除非后续规则明确要公开。

### 3. 出征队员提交任务票

- UI 入口：`MISSION_VOTE` 阶段的“任务成功 / 任务失败”按钮。
- 当前状态：按钮已灰置；领域模型已有 `AvalonGame.submit_mission_vote()`。
- 缺失项：
  - `CommandGateway` 支持 `mission_vote` 命令。
  - 只有当前队伍成员可提交任务票。
  - 好人阵营是否允许提交失败票需要规则层明确。当前 `friend_flexible` 快照只表达 `can_submit_fail`，但应用层尚未执行。
  - 投票完成后广播比分变化、任务失败票数量和下一阶段。

### 4. 任务结果复盘后进入下一轮

- UI 入口：`MISSION_RESULT_DISCUSSION` 阶段的“进入下一轮”按钮。
- 当前状态：按钮已灰置；领域模型已有 `AvalonGame.continue_after_mission_result()`。
- 缺失项：
  - `CommandGateway` 支持 `continue_after_result` 命令。
  - 明确谁可以推进：建议第一版由房主推进，后续可改为讨论计时或发言轮结束自动推进。
  - 推进后重置当前队伍、票、队长，并广播下一轮 `TEAM_PROPOSAL`。

### 5. 刺客刺杀梅林

- UI 入口：`ASSASSINATION` 阶段的“选择刺杀目标”按钮。
- 当前状态：按钮已灰置；领域模型已有 `AvalonGame.submit_assassination()`。
- 缺失项：
  - `CommandGateway` 支持 `assassinate` 命令。
  - 前端刺杀目标弹层启用。
  - 只有刺客可提交，且只能提交一次。
  - 提交后进入 `GAME_OVER` 并广播胜利方。

### 6. 公开历史和任务结果事件

- UI 入口：历史弹层、法官公告、任务结果复盘文案。
- 当前状态：页面已保留历史入口，但 `public_timeline` 仍为空。
- 缺失项：
  - 应用层事件投影公开历史：开局、队长、队伍名单、组队是否通过、任务成功/失败、失败票数量、比分、刺杀结果。
  - 历史不得泄漏秘密任务票提交者、未公开身份表或夜间可见信息。
  - 快照需要稳定返回 `public_timeline`。

### 7. 终局身份公开

- UI 入口：终局阶段、信息弹层、历史弹层。
- 当前状态：`GAME_OVER` 只显示胜利方，未公开全员身份。
- 缺失项：
  - 快照新增终局 `reveal_roles`，仅在 `GAME_OVER` 返回。
  - 前端终局展示所有玩家身份与阵营。
  - 测试确保非终局不泄漏全员身份。

## P1：不一定阻断规则闭环，但阻断成熟线上体验

### 8. 文字公屏

- UI 已恢复但发送框灰置。
- 需要服务端接收、广播、持久化或短期保留聊天消息。
- 需要按阶段和发言控制决定谁可发言。

### 9. 语音客户端接入

- 顶部语音和扬声器按钮已灰置。
- 后端已有 `/voice-token`，但前端未接 LiveKit 客户端。
- 需要按 `voice_state.can_publish_audio` 控制麦克风发布权限。

### 10. 发言控制和在线状态

- 旧产品目标包含发言控制、在线状态、断线重连提示。
- 当前 v2 只有 WebSocket 鉴权连接，没有公开在线列表、发言人、发言结束或强制切换命令。
- 需要快照新增 `online_state`、`speaker_state` 或等价字段。

### 11. 房主治理操作

- 旧 UI 有踢人、重置、复制邀请等治理入口。
- 当前 v2 只保留重置和邀请链接，缺少踢人、转移房主、游戏开始前退出/重连复用身份。

### 12. 私人标记

- 旧 UI 有私人标记入口，当前按钮灰置。
- 第一版可以先做纯本地 `localStorage`，后续再考虑服务端跨设备同步。

## 完整一局覆盖检查

完成一整局游戏的最小路径是：

1. 玩家加入房间。
2. 玩家准备，房主开局。
3. 每个玩家查看自己的身份和可见信息。
4. 队长选择队伍。
5. 全员对队伍投票。
6. 若队伍被否决，切换队长并重新组队。
7. 若队伍通过，出征队员提交任务票。
8. 服务端结算任务结果并更新比分。
9. 未达到终局时进入下一轮。
10. 正义三次任务成功后进入刺杀。
11. 刺客提交刺杀目标。
12. 服务端结算胜负并终局公开身份。

当前 v2 已覆盖第 1-3 步的主要链路。第 4-12 步的核心规则在领域模型里存在，但没有应用层命令、前端可用操作和完整公开事件投影，因此当前版本不能完成一整局游戏。

本文件的 P0 第 1-7 项补齐后，规则闭环可以覆盖第 4-12 步，满足“能完整完成一局”的最低要求。P1 第 8-12 项用于恢复朋友局线上产品体验，其中语音、文字、公屏历史、发言控制和在线状态会显著影响真实可玩性，应在 P0 后紧接排期。
